# 卡密管理

一个项目对应一次团队任务。管理员新建项目、填写任务说明、选择协助成员，然后批量粘贴卡密；字符串和链接都按一行一份处理。

- `card_key:view`：进入页面；协助成员领取并确认消耗自己的卡密。
- `card_key:manage`：新建/编辑项目、导入、查看全部记录，自动包含查看权限，无需额外勾选。
- 协助成员可以选择“全员”，所有拥有查看权限的团队成员都可参与。
- 成员只看到参与项目及自己的领取记录；被移出项目后仍能查看和完成此前已领取的卡密。
- 一次领取一份，每个成员在同一项目最多有一份未确认卡密。重复点击领取返回同一份，刷新后可在待消耗区找回。
- 领取先锁定，实际使用后再确认消耗。临时退出任务可点击“归还未使用”，确认尚未使用后重新入池；已消耗不可归还，不确定是否使用时不要归还。系统不验证外部服务实际使用结果。
- 卡密内容加密存储。全库按去除首尾空白后的完整内容去重；大小写保留，链接不做改写。同一内容不能换项目重复导入。
- 领取使用数据库条件更新，未确认持有人和卡密指纹均有唯一约束，防止并发重复领取/导入。
- 项目结束后停止导入和新领取，仍可归还或确认此前领取的卡密。管理员和领取人可归还未消耗卡密；流转记录保留领取、归还、消耗的操作人及时间。没有自动释放或删除按钮。

首次部署执行 `alembic upgrade head` 并重启后端；管理员在团队角色中授予相关权限，成员刷新登录权限后进入“卡密管理”。

## 权限保存报错排查

若保存角色时报“包含未知权限标识符”，例如 `card_key:view`、`card_key:manage`、`work_item:view` 或 `work_item:manage`，检查后端是否已更新并重启。这些标识由后端 `PREDEFINED_PERMISSIONS` 校验；数据库升级或刷新前端不能让旧后端识别新标识。不要通过取消勾选或删除权限来绕过报错。

更新后重新保存角色。角色保存成功但成员菜单未更新时，让成员退出后重新登录，重新获取权限。仅查看权限不允许新建项目、导入卡密或新建备忘；卡密的查看权限允许参与成员领取、消耗和归还自己的卡密。

在 `backend` 目录执行 `python -m pytest tests/test_permission_registry.py tests/test_card_keys.py tests/test_work_items.py -q`，验证前后端权限清单、角色保存及相关操作边界。
