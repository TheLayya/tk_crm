# 2026-10-06：成员终端继承的账号与节点可见性

## 团队服务器只读证据

团队服务器及演示服务器均已安装 1.1.14，前后端健康；不是未升级问题。普通成员 `xingchen` 具有 op_account:view、proxy_node:view，角色范围 self。

旧接口查询返回账号 0、节点 0。该成员名下有效终端绑定了 45 个运营账号、20 个不同节点；账号 registrant/operator 没有匹配登录 username，全部节点 created_by 为旧数据空值。旧过滤遗漏了终端 owner_id 继承。

根因核查只读取归属和数量，没有读取密码、重写业务记录、调整角色、触发线上采集或升级。随后在团队容器的临时 Python 进程中执行候选范围辅助代码，SQLite 使用 mode=ro，结果账号 45、节点 20。没有保存候选代码至服务器或替换服务代码。

## 最终修复

- `asset_scope_service` 统一 self/dept/all：账号可见性来自 registrant/operator 或有效非删除终端 owner_id，账号不会因为共享节点而获得可见性。
- 节点可见性来自创建人、有效终端所属人、可见账号及原有可见邮箱关联。共享节点内只返回本范围账号/终端。
- 账号列表、统计、导出、编辑/删除、视频/日志/关联历史、采集、批量分配、邮箱账号选项和总览保持同一范围。
- 节点列表和绑定下拉先在 SQL 过滤再分页；节点详情、统计、导出、关联/删除也采用一致范围。删除共享节点保护其他成员的账号、邮箱和终端。
- 账号和终端创建/编辑校验目标终端/节点，拒绝靠绑定别人的节点扩大可见性的旧入口。关联授权在写入前执行。
- 采集任务新增 `created_by`，迁移 `20261006_0023 -> 20261006_0022`；新任务由发起人/其部门范围查询，旧任务归属为空时普通成员访问被拒绝，all 范围可查看。
- 没有修改真实业务记录，保留历史使用人文字。安装后会从终端归属恢复可见性，无需重导账号或将成员角色改为 all。

本轮权限语义变更来自独立审查确认的旧终端归属兼容缺陷；没有把 node ownership 当作 account ownership。
