# 邮箱批量使用状态与手动检测状态

用户要求邮箱管理增加批量修改使用状态和检测状态，并明确检测状态为人工修改。本功能并入尚未公开上传的 1.1.21；旧候选和验证证据保留在 `.orchestration/release-1.1.21`，最终候选使用 `.orchestration/release-1.1.21-final` 重新构建。

- 邮箱列表选择后提供两个批量入口，统一窗口显示邮箱数量、固定名单及目标状态；只发送打开窗口时的邮箱 ID。
- `POST /api/emails/batch-status` 每次仅修改使用状态或检测状态之一，1–500 个正整数 ID，按顺序去重；所有邮箱须存在且位于当前成员数据范围，整批校验和提交。
- 使用状态支持闲置、使用中、锁定、废弃。出售继续使用现有批量售出；已出售或领取中的邮箱整批提示冲突，不覆盖交易或领取资料。
- 手动检测状态支持正常、封禁、验证、未注册、检测失败，以及显式 null 清空为未检测；适用于全部可见邮箱，不发起外部探测。人工状态以既有 raw 字段记录“手动标记”，清空旧检测时间，UI 显示“手动”及说明，避免当作实际检测。
- 自动检测和人工检测状态写入共用现有 Gmail 检测锁，先拿锁再读取；进行中返回 429 供重试，避免旧响应覆盖人工标记或出现混合元数据。只改使用状态时不占检测锁。
- 需要 `email:manage` 权限，日志记录为邮箱管理 UPDATE。密码、2FA、关联、领取、采购和出售信息保持原值。
- 提交防重复并锁定关闭；冲突保留目标和名单，成功清空选择并刷新一次。手机工具栏换行显示，最后检测保留实际探测时间语义。

没有新增依赖或数据库迁移。新增后端权限/数据范围、验证、500 条边界、原子性、并发售出/领取、手动/自动检测协调及日志回归；浏览器合成 API 回归覆盖窗口快照、单字段请求、关闭锁、错误重试、null 清空、原检测入口和手机布局。最终完整门禁和资产证据见 1.1.21 最终发布记录。
