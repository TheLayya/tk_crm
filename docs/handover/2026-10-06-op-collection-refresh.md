# 2026-10-06：完整运营采集与统计刷新

## 已确认的问题

1. 导入、创建、单个采集、批量采集和定时任务调用同一个 collector；原实现把资料 `video_count == 0` 当成不需要请求视频，且资料阶段提交时可能仍保留上次成功状态。
2. 展开的视频组件只观察账号 ID/来源。资料采集后先读取了空视频结果时，后续视频写入不会刷新同一组件；手机详情还保留旧行对象。
3. 运营账号粉丝变化只从授权同名监控账号的历史中计算，独立运营账号没有自己的基线。

只读生产核查：两台服务器容器和更新状态均为 1.1.13；截图所选账号在团队服务器已有 20 条自己的视频，视频保存时间晚于资料时间约 3 秒。展开区的 0 条是旧缓存；后续一次手动采集资料接口返回非 JSON，旧视频仍保留。附带演示 URL 与所选账号实际服务器不一致，不能仅凭附带 URL 判断业务库。本轮没有部署、重启或触发线上采集。

## 修复

- 每次 TikTok 采集都尝试资料和视频；零值资料不跳过视频。资料失败但身份缓存有效时仍尝试视频，最终保留资料失败原因；新账号缺身份时如实失败。
- 视频完成前保持 pending；已知有视频而视频接口空结果不算完整成功。持久化异常 rollback，不覆盖旧视频完成时间。
- 修改账号身份会失效缓存 ID、粉丝基线和采集时间；异步旧请求不会覆盖新身份。视频历史保留，未重新采集前不进入昨日摘要。
- 新增 nullable `previous_follower_count` 与迁移 `20261006_0022`；仅前一次有效采集建立粉丝基线，第一次显示暂无对比。资料缺少有效粉丝统计不再伪造 0。
- 桌面展开和手机详情按视频采集时间刷新组件；任务结束同步最新行。页面可见时每 30 秒静默更新，隐藏时暂停，离开页面清定时器，旧请求不覆盖新查询。
- 视频条数沿用系统“默认监控视频数”；本轮“完整”指账号资料和视频两个采集部分，没有改为无限历史视频抓取。
