## 失败记录

首轮 `release-audit-1.1.16-resume.log` 实际 exit 1：阳性恢复进程已就绪，缺失 `.env` 的阴性夹具在 `RunFixture` 中发生未处理异常，未满足 `WaitForExit(5000) && ExitCode != 0`。Windows 崩溃处理可能延迟退出，但未单独证实 WER 为唯一原因。修复仅让夹具显式失败，未放宽断言；独立回滚和旧安装器完整审计随后取得 exit 0，原失败日志保留。

首次真实在线专项 `online-update-1.1.16-resume.log` exit 1：真实下载坏 SHA 正确拒绝，新后端健康，但新窗口在 90 秒内没有就绪回执；生产更新器恢复程序/数据并启动旧 1.1.15，`recovery-ready.json` 正确返回旧版本。WebView2 初始化存在间歇现象，未证明共享配置目录是唯一原因。

原包第二轮 `online-update-1.1.16-rerun.log` 新版本就绪和 `completed` 均存在，但脚本仍 exit 1。隔离最小实验确认 PowerShell `Start-Process` 重定向 stdout/stderr 后轮询退出，未提前持进程句柄会得到 `ExitCode=null`；相同参数提前读取 `Handle` 得到整数 0。脚本现提前持句柄，等待后要求退出码为整数；坏 SHA 必须真实退出码 1，阳性仍要求真实 0。未修改生产资产或把 `completed` 当退出码替代。修正后完整专项取得实际 exit 0，正常更新、新版回执/健康、加密记录/配置/标记、历史和卸载保留均通过。首次间歇失败原因仍未完全确定，不以最终通过声称零故障。
