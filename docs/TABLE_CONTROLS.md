# 表格排序、筛选与列设置

所有现有表格统一使用 Element Plus 表格控件。主列表、详情历史、视频表、导入结果、日志和统计报表均已接入；未挂路由的三个旧页面也同步接入。

## 使用

- 点击数据列表头的排序箭头切换升序、降序或取消排序。表格上方显示当前排序。
- 点击表头的筛选图标，填写条件后点击“查询”。文本支持包含搜索；状态支持多选；数值支持上下限；日期支持起止日期。条件可以组合使用。
- 复合列可选择具体字段，例如“采购 / 出售”可选择渠道、金额或日期；也可按选中的字段升序或降序排列。
- 条件生效时图标高亮，表格上方显示条件标签。点击标签的关闭按钮移除一个条件；“重置查询”同时清除表头筛选和排序。
- 点击“列设置”勾选显隐，拖动或使用上下箭头调整顺序。拖动表头边缘调整列宽。“恢复默认布局”恢复默认列顺序、显隐和宽度。
- 选择、展开和操作列保留固定位置。图片、纯趋势图、密码和 2FA 等凭据列可调整布局，其表头不提供值查询。

列布局按当前站点、登录用户和表格分别保存在浏览器本地；排序和筛选在当前浏览器会话中保存，刷新后恢复。更换浏览器或电脑不会同步这些设置。运营账号原有列显隐设置会自动迁移。

页面顶部已有查询与表头条件组合生效；终端、节点的页面“清空筛选 / 重置”会一并清除表头查询。列设置不改变数据权限。

## 查询规则

分页表在后端完成筛选、排序和计数后再分页。全量加载的小表及统计报表在前端处理完整集合，再选择当前页。数值使用真实数值比较，日期使用时间比较；空值排在末尾，相同值保持稳定顺序。

“昨日视频流量”继续逐条展示已采集视频的累计播放量；排序与数值范围筛选按这些播放量的合计进行，不代表昨日新增播放量。粉丝变化继续采用页面原有的变化口径。

## 开发接入

共享组件为 `frontend/src/components/CrmTable.vue`，查询逻辑为 `frontend/src/composables/useTableQuery.js` 和 `frontend/src/utils/tableState.js`。

每个表格使用稳定 `table-id`，每列提供稳定 `column-key`、真实 `prop` 和 `filter-type`。单元格内容保留原有插槽。复合列通过 `table-fields` 指定可查询字段，枚举通过 `filter-options` 指定业务值。`table-tools-disabled` 禁用值查询；`default-hidden` 指定默认隐藏；`legacy-column-group` 用于兼容旧运营账号设置。

后端列表查询支持 `sort_by`、`sort_order=asc|desc` 和 `table_filters` JSON。后端仅接受对应资源白名单中的字段和有效类型，非法参数返回 422。无需数据库迁移或新依赖。

普通字段使用 SQL 查询后分页；部分复杂派生字段和加密卡密查询会处理完整权限范围集合后分页。数据量增长时应将派生计算进一步下推 SQL，避免完整集合占用内存。

## 回归检查

```text
node frontend/tests/table-state.cjs
node frontend/tests/table-controls.cjs
```

浏览器检查要求本地 Vite 服务，默认 `http://127.0.0.1:5186`，可用 `TKCRM_UI_URL` 修改地址。检查中的 API 均使用合成数据拦截，不访问真实业务数据。后端专项位于 `backend/tests/test_table_account_queries.py` 和 `backend/tests/test_table_asset_queries.py`。
