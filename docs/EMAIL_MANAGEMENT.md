# 邮箱管理

邮箱是独立资源，入口为 `/emails`，不再作为运营账号列表中的平台。

## 使用

- 邮箱可绑定手机终端及节点，同一手机或节点可供多个邮箱共享；编辑时清空即可解绑，更换和解绑保留轨迹。
- 支持采购渠道、成本、日期，出售客户、金额、日期、出售人及使用人；金额不能为负数。
- 新增邮箱和批量导入均必须填写采购渠道、采购成本，免费来源请明确填写 0；编辑历史邮箱时不强制补齐采购信息。
- 使用状态选择“已出售”时才显示出售表单，出售客户、金额、日期和出售人全部必填；编辑已出售邮箱同样校验，切回其他状态保留出售资料用于追溯。已出售邮箱不能新增运营账号绑定。
- 勾选邮箱后可“批量售出”：统一填写客户、单个邮箱售价、出售人和日期，自动显示数量与总金额；出售人默认当前用户、日期默认本地今天。有成员查看权限时可改选出售人。每页可显示 50/100/200/500 条，表头可全选当前页；翻页或刷新后重新选择。
- 批量售出整批校验、整批保存，选中邮箱包含无权访问、不存在、已出售或正在被领取的记录时整批拒绝，避免覆盖售卖记录或部分售出。成功后自动复制交付资料，并保留可再次复制的交付窗口，即使当前筛选已隐藏售出邮箱也可完成交付。复制失败不影响已保存的售卖信息，可重试或手动复制窗口中的资料。
- “复制选中资料”也可直接批量交付，格式为 `邮箱----密码----辅助邮箱----2FA 密钥`，每行一个邮箱，空字段留空；只包含登录资料。原有单条“复制资料”仍使用带字段名称的格式。

- 新增、编辑或批量导入邮箱；密码与 2FA 使用现有字段加密服务保存。
- 展开邮箱后，有有效 2FA 密钥时直接显示当前六位验证码和倒计时，到期自动换码；可分别复制验证码或 2FA 密钥。密钥默认遮罩，无效密钥会提示并保留复制。收起详情、翻页或离开页面后停止换码。
- 邮箱新增独立的 `CK (Cookie)` 字段，支持原文保存 Cookie JSON 或 Cookie Header；列表的 CK 列显示是否已保存，并提供“复制 CK”和“取加号”。展开详情后默认遮罩，点“显示 CK”可查看；编辑中直接修改或清空后保存。CK 使用现有字段加密服务及长文本列保存，与备注分开；历史备注保留原文，可手动移到 CK，系统不自动猜测或删除备注。
- 卡密项目“注册完成”窗口可直接回填 CK：留空保留原值，填写覆盖保存；其他字段和领取释放流程不变。详见 `CARD_KEY_MANAGEMENT.md`。
- “取加号”从现有 CK 在当前页面中提取 Flow 所需 Cookie，顺序固定为 `__Secure-1PSID::SID::OSID`，存在 `__Secure-1PSIDTS` 时追加第四段。提取窗口可复制或手动选中结果；缺少必需项或格式有误会明确提示，不返回部分结果。编辑窗口可直接提取尚未保存的 CK。
- 支持 Cookie JSON 数组、Cookie Header，以及带 `cookies` / `refreshCookie` 的导出结构；有域、路径、过期、分区元数据时按 Flow 范围过滤。仅提取已有凭据，不自动登录或检测 Cookie 有效性。准备 CK 时可在 Chrome 无痕窗口登录 Flow；导出插件需在详情里开启“在无痕模式下启用”。是否含 TS 不能用来保证 Cookie 寿命。
- 导入默认“逐行识别混合格式”，一批可混合三至六项及 `----`、`|`、`:`、英文逗号、中文逗号、Tab 分隔。三项的第三项是邮箱时保存为辅助邮箱，其他内容原样保留为 2FA；标准四项默认按 `邮箱/密码/辅助邮箱/2FA` 处理，自动模式遇到明确国家代码/名称时按带国家四项处理，选择“邮箱/密码/辅助邮箱/2FA（强制）”可固定第四项为 2FA。另支持四项 `邮箱/密码/辅助邮箱或2FA/国家`、五项 `邮箱/密码/辅助邮箱或2FA/2FA/国家`，国家支持代码或名称；格式有歧义时可手动指定字段格式和分隔符。
- 连续 `----` 中的空字段按位置保留，辅助邮箱可填 `null` 或留空；第三项为 2FA 且第四项留空时仍保留该密钥。密码按原文保存，已有邮箱和同批重复邮箱自动跳过，错误行单独显示。
- 六项格式为 `邮箱/密码/辅助邮箱/2FA/注册时间/国家`。注册时间支持年份、日期或完整日期时间。采购渠道和采购成本统一填写并应用于整批邮箱；每条记录保存单个邮箱成本，免费来源请填 0。
- 从邮箱展开区关联运营账号；同一邮箱可关联多个平台账号。
- 解绑保留关联时间、解绑时间及操作人，运营账号展开区也能查看邮箱关联。
- 勾选当前页邮箱后，可“批量修改使用状态”，统一设为闲置、使用中、锁定或废弃，每次最多 500 个。整批验证可见范围和当前状态，已出售或领取中的邮箱需先处理后重新选择；登记出售继续使用“批量售出”，交易资料保持完整。
- 批量修改固定打开窗口时的邮箱名单，显示数量与目标状态；确认后整批保存，失败保留窗口供重试。只修改使用状态，凭据、关联、领取和采购/出售资料保持原值，操作记录进入团队日志。需要 `email:manage` 权限并遵循数据范围。
- 管理员可批量设置“卡密领取”：选择 1–500 个邮箱后开启或禁止。开启后仍需满足闲置、未领取、未注册目标平台才会被卡密项目使用；关闭时若选中邮箱已有领取记录，整批拒绝，不会中断正在注册的邮箱。普通成员看不到此列和批量操作。

## 数据和权限

执行 `alembic upgrade head`，迁移 `20261001_0004` 创建独立邮箱表和关联历史表，并复制原 Gmail 记录及密文凭据。原记录不删除，旧 API 保持兼容；运营账号页面默认排除 Gmail。

角色权限：`email:view`、`email:manage`、`email:import`。绑定/解绑还需要 `op_account:edit`，选择账号需要 `op_account:view`。邮箱及关联遵循角色的数据范围。

CK 查看、复制和本地提取沿用 `email:view` 及邮箱数据范围，保存与清空需要 `email:manage`。CK 不参与表格排序和筛选，也不自动加入现有“复制资料”或批量交付文本。使用新版本前须执行 CK 与卡密领取开关的 Alembic 迁移（当前 head 为 `20261114_0030`）。

已有关联历史的邮箱或运营账号不能直接删除，以避免丢失追溯记录；邮箱可标记为废弃。

现有运营账号的手填绑定邮箱字段暂时保留兼容，不自动猜测或生成关联。正式关联以独立邮箱资源和关联历史为准。
