# 邮箱管理

邮箱是独立资源，入口为 `/emails`，不再作为运营账号列表中的平台。

## 使用

- 邮箱可绑定手机终端及节点，同一手机或节点可供多个邮箱共享；编辑时清空即可解绑，更换和解绑保留轨迹。这些关联不改变 Gmail 检测的网络代理。
- 支持采购渠道、成本、日期，出售客户、金额、日期、出售人及使用人；金额不能为负数。
- 新增邮箱和批量导入均必须填写采购渠道、采购成本，免费来源请明确填写 0；编辑历史邮箱时不强制补齐采购信息。
- 使用状态选择“已出售”时才显示出售表单，出售客户、金额、日期和出售人全部必填；编辑已出售邮箱同样校验，切回其他状态保留出售资料用于追溯。已出售邮箱不能新增运营账号绑定。

- 新增、编辑或批量导入邮箱；密码与 2FA 使用现有字段加密服务保存。
- 导入格式：`邮箱:密码:辅助邮箱:2FA:注册时间:国家`，注册时间可只填年份，也支持完整日期/时间。采购渠道和采购成本在导入窗口统一填写，二者必填并应用于整批邮箱；每个邮箱记录的是单个邮箱成本，免费来源可明确填写 0。
- 同时兼容 `|`、`----`、`:` 分隔，每行自动识别，可混合粘贴。三种格式均支持四字段或六字段，只有前四项时不需要补时间、国家。
- 从邮箱展开区关联运营账号；同一邮箱可关联多个平台账号。
- 解绑保留关联时间、解绑时间及操作人，运营账号展开区也能查看邮箱关联。
- 检测状态和使用状态分开：第三方检测不会覆盖闲置、使用中、锁定、废弃状态。
- Gmail 检测仍使用 gmail0918.top，确认后仅发送邮箱地址，不发送密码或 2FA。详见 `GMAIL_CHECKER.md`。

## 数据和权限

执行 `alembic upgrade head`，迁移 `20261001_0004` 创建独立邮箱表和关联历史表，并复制原 Gmail 记录及密文凭据。原记录不删除，旧 API 保持兼容；运营账号页面默认排除 Gmail。

角色权限：`email:view`、`email:manage`、`email:import`、`email:check`。绑定/解绑还需要 `op_account:edit`，选择账号需要 `op_account:view`。邮箱及关联遵循角色的数据范围。

已有关联历史的邮箱或运营账号不能直接删除，以避免丢失追溯记录；邮箱可标记为废弃。

现有运营账号的手填绑定邮箱字段暂时保留兼容，不自动猜测或生成关联。正式关联以独立邮箱资源和关联历史为准。
